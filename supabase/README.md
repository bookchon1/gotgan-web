# 곳간 — Supabase 스키마

새 Supabase 프로젝트의 **SQL Editor** 에서 아래 순서로 실행하세요.

| 순서 | 파일 | 내용 |
|------|------|------|
| 1 | `schema.sql` | 전체 테이블 생성 (조직·직원·업무·사업·예산·전표·급여·결재·문서·일정 등) |
| 2 | `rls.sql` | Row Level Security + 권한 헬퍼 함수 (관리자/일반/담당 구분) |
| 3 | `seed.sql` | 초기 데이터 (사업자 3곳, 부서, 직원 12명, 권한) |
| 4 | `functions.sql` | RPC (급여 전월복사·상신, 출퇴근 체크) |

각 파일을 통째로 복사해 붙여넣고 **Run** 하면 됩니다. 여러 번 실행해도 안전(멱등)합니다.

## 로그인 계정 만들기 (중요)

직원 명부는 들어갔지만 **로그인 계정은 별도**입니다:

1. Supabase → **Authentication → Users → Add user** 로 직원 이메일/비밀번호 생성
2. 그 계정을 직원과 연결 (SQL Editor):
   ```sql
   update public.employees
     set auth_user_id = '<auth user uuid>', email = '<그 이메일>'
     where name = '이윤정';
   ```
3. 최소 관리자 1명(이윤정)을 연결하면 로그인 + 전체 기능 확인 가능.

## 권한 구조 (요약)

- **관리자(admin)**: 전 화면. (김도래·김성헌·이윤정·김다래)
- **담당(admin_grants)**: 인사(hr)·노무(labor)·회계(accounting) 세분 — 이윤정이 전부 담당.
- **일반(user)**: 업무·문서·결재·일정 + 본인 부서 현황. 급여·연차·근태는 **본인 것만**. 회계 전표 접근 불가.
- 민감 쓰기(급여·전표)는 RLS 를 열지 않고 **RPC** 로만 — 서버에서 권한 재검증.

> 로컬 PostgreSQL 16 에서 스키마·RLS·RPC 동작을 검증했습니다
> (일반 사용자의 회계·타인급여 차단, 담당자 전체열람, 전월복사/출퇴근 RPC, 권한없는 호출 거부).
